GraphRAG & Self-Corrective Hybrid Retrieval Engine

Production-style retrieval platform uniting a Neo4j knowledge graph, Qdrant dense+sparse vectors, RRF fusion, cross-encoder reranking and a self-corrective CRAG loop (LangGraph) with continuous Ragas/DeepEval evaluation — built end-to-end on free, self-hostable resources.

Vaibhav Tiwari · August 2026 · Python 3.11 · FastAPI · Streamlit · Celery/Redis · Docker

The problem with vector-only RAG — and the fix

  • No entity awareness — multi-hop answers ("which supplier caused incident X?") span 3+ documents that vector search retrieves in isolation.
  • Keyword blindness — SKUs, incident IDs and policy codes defeat semantic embeddings.
  • Blind generation — irrelevant context silently poisons answers; no measurement of retrieval quality.
  • Four fused signals: dense ANN + sparse lexical + 2-hop graph traversal + cross-encoder rerank, merged with Reciprocal Rank Fusion.
  • Self-correction: every retrieval is graded; weak evidence triggers query rewriting, then a keyless DuckDuckGo fallback.
  • Continuous evaluation: Ragas faithfulness / precision / recall over a golden multi-hop benchmark, CI-ready.
